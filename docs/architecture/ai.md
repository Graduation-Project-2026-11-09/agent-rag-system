# AI の構成（Agentic RAG）

> **このドキュメントは一部未定。** 計画書（プロジェクト計画書）に書かれた方針をまとめたもの。「未定」の項目は、決まりしだい更新する。

## 方針（計画書より）
- 一般的な RAG に AI エージェントの機能を組み合わせた **Agentic RAG** を採用する
- 回答には**必ず根拠資料を表示**する。根拠が見つからない場合は推測で答えず、担当部署への問い合わせを提案する
- AI は**自動で送信・申請しない**。問い合わせは利用者が確認・承認してから送る
- 通常の RAG と Agentic RAG を**切り替えられるようにし**、同じ質問で「必要な情報を取得できた割合・回答の正確性・回答時間・料金」を比較する
- 開発・検証では**ダミー資料だけ**を使う（外部の AI に本物の社内資料を送らない）

## エージェント
### 検索Agent
質問を分析し、どの資料を・どんな言葉で検索するかを判断する。

```
質問
 │
 ▼
① 質問分析 ─── 何を調べればよいか（観点）を洗い出す
 │              例:「結婚した」→ 氏名変更・扶養・社会保険・慶弔制度
 ▼
② 検索語の展開 ─ 利用者の言葉を、社内資料の正式な言葉に言い換える
 │
 ▼
③ 検索 ─────── pgvector でベクトル検索（利用者が見られる資料だけ）
 │
 ▼
④ 充足度の評価 ─ 回答に必要な情報がそろったか判断する
 │      │
 │      └─ 足りない → 条件を変えて ②へ（再検索は最大 3 回）
 ▼
⑤ 回答の作成 ─── 観点ごとに整理し、根拠資料の番号を付ける
                  次に行う手続きを、期限・担当部署つきのチェックリストにする
```
①〜④の過程は画面にリアルタイムで表示する（質問送信から 3 秒以内に表示を開始する）。

### 業務支援Agent
資料だけでは解決できない場合に、次の行動を提案する。
- 「担当部署への問い合わせを作成しますか？」と提案する
- 会話の内容・確認済みの資料・不明点から、宛先部署・件名・本文の下書きを作る
- 利用者が編集し、「承認して送信」を押したときだけ送信する

## 資料の取り込み（worker）
```
アップロード → S3 に原本を保存
   → テキスト抽出 → チャンク分割 → ベクトル化（OpenAI）→ pgvector に保存
   → 検索可能になる
```
- まず PDF・Word・テキストに対応する。Excel・PowerPoint はその後
- 読み取れない資料はエラーの理由を表示し、取り込み直せるようにする
- 資料ごとに公開範囲（全員 / 部署限定）を持ち、検索のときに絞り込む
- 改定した場合は新しい版で検索する（古い版は履歴として残す）

## 目標値（計画書より・案）
| 項目 | 目標 |
|---|---|
| 検索過程の表示開始 | 質問送信から 3 秒以内 |
| 回答完了 | 再検索を含めて平均 30 秒以内 |
| 同時利用 | 50 名程度 |

## 使用するモデル（2026-11-09 決定）
すべて OpenAI API。料金は公式の Standard 料金（100 万トークンあたり、2026-11-09 時点）。

| 役割 | モデル | 料金（入力 / 出力） | 理由 |
|---|---|---|---|
| ① 質問分析・② 検索語の展開 | `gpt-6-luna` | $0.10 / $0.50 | 決まった形（JSON）の出力で、速さが大事（3 秒以内に検索過程を表示） |
| ④ 充足度の評価 | `gpt-6-luna` | 同上 | 「足りる・足りない」の判断。1 回の質問で最大 4 回呼ぶ |
| ⑤ 回答の作成 | `gpt-6-luna` | 同上 | 費用を最優先。品質が足りなければ `gpt-6.1-terra`（$1.00 / $5.00）に変える |
| 問い合わせ文の下書き | `gpt-6-luna` | 同上 | 同上 |
| 資料・検索語のベクトル化 | `text-embedding-3-large` | $0.13 | 検索の精度を優先（3072 次元。DB は `halfvec(3072)`） |

- モデル名は環境変数で切り替える: `OPENAI_CHAT_MODEL_FAST`（①②④）、`OPENAI_CHAT_MODEL_ANSWER`（⑤・下書き）、`OPENAI_EMBEDDING_MODEL`。使ったモデルは `agent_runs.config` に記録する
- 応答を速くするため、luna の推論の深さ（reasoning effort）は `none` か `low` から試す
- 費用の目安: 質問 1 回 約 $0.0023（約 0.3 円）、月 1,000 問で約 $2.3。資料 300 件のベクトル化は 1 回 約 $2.3
- gpt-4o・gpt-4.1・gpt-5-mini などは OpenAI が廃止を予定しているので使わない
- 評価（[db.md 4.9](db.md#49-評価通常の-rag-と-agentic-rag-の比較)）で、回答の作成を luna と terra で比べ、品質が足りなければ terra に変える

## 費用の対策
- 再検索の回数に上限（3 回）を設ける
- AI の利用量（トークン数）を記録し、利用履歴で確認できるようにする
- OpenAI の API キーに利用上限を設定する

## DB との関係
資料のベクトル化から回答までの各段階で、どのテーブルに何を書くかは [db.md の 11 章](db.md#11-ai資料のベクトル化検索回答とテーブル) にまとめている（チャンクの作り方・ベクトルの使い回し・公開範囲の絞り込み・評価の記録を含む）。

## 未定の項目
| 項目 | 検討すること |
|---|---|
| チャンクの分割方法 | 文字数・重なり・見出し単位で分けるか |
| 検索方式 | ベクトル検索のみか、キーワード検索と組み合わせる（ハイブリッド検索）か |
| エージェントの実装方法 | ライブラリ（OpenAI Agents SDK、LangGraph など）を使うか、自作するか |
| 回答のストリーミング方式 | SSE（Server-Sent Events）など。Gunicorn の設定に影響する |
| プロンプトの管理 | コードに書くか、ファイルで管理するか。変更履歴の残し方 |
| 評価の方法 | 評価用の質問セットと正解、通常 RAG との比較の手順 |
