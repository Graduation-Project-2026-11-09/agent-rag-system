## 2. 定期作業

### 2.1 日次
- 9:00 監視ダッシュボードでアラートの有無を確認する
- 9:00 前日のバックアップが成功したか確認する

### 2.2 月次
- 第2水曜日の夜 OS のセキュリティ更新を適用する（22:00〜24:00、事前に全社にお知らせする）
- 月末 アカウントの棚卸し（退職者のアカウントが停止されているか）

### 2.3 年次
- 9月 バックアップからの復元テスト
- 3月 サーバーの証明書の更新状況の確認

## 3. 障害対応

### 3.1 障害の等級
| 等級 | 基準 | 初動の目標 |
| --- | --- | --- |
| 重大 | 全社で業務が止まっている | 15分以内 |
| 中 | 一部の部署・機能が使えない | 1時間以内 |
| 軽微 | 回避策がある | 翌営業日 |

### 3.2 初動の手順
1. 監視のアラート又は問い合わせで障害を確認する
2. チャットの「障害対応」チャンネルに、発生時刻・症状・影響範囲を書く
3. 重大障害の場合は、情報システム部長に電話する
4. 社内ポータルのお知らせで、利用者に障害の発生を知らせる

### 3.3 復旧後
復旧したら、利用者にお知らせで知らせ、3営業日以内に障害報告書を作成する。報告書には、原因・対応の経過・再発防止策を書く。

## 4. 夜間・休日の当番
夜間・休日は、当番表に従って1人が待機する。当番は、監視のアラートが電話で届いたら30分以内に対応を始める。当番手当は「賃金規程」による。

## 5. バックアップ
- ファイルサーバー：毎日 2:00 に差分、毎週日曜日に全体のバックアップを取得し、30日分保管する
- 基幹システム：クラウドの機能で1時間ごとにスナップショットを取得し、7日分保管する
